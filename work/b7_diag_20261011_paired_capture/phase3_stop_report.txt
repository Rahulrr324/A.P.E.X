VERIFICATION — ARTIFACT CANNOT OVERWRITE EXISTING EVIDENCE
  1. Path scope: make_paired_artifact_path(run_dir) returns run_dir + "/paired_samples.csv",
     and run_dir is the run-owned directory created by create_run_owned_blob() under
     build/bm_b7_diagnostic/ (validated by validate_diagnostic_dir before creation).
  2. Isolation: before opening for write, validate_diagnostic_path(path) is checked,
     which enforces: under build/bm_b7_diagnostic/, no absolute paths, no "..", and
     forbids any path containing campaign/historical/production markers
     (g7-campaign, g7cam, reports, records, .jsonl, evidence_manifest, gate_results,
     tiny_dense_2l_weights.bin). So the artifact cannot target historical/production
     paths even if run_dir were somehow confused.
  3. No-overwrite: the file is created with exclusive_create_file(path) (O_CREAT|O_EXCL
     on POSIX; _O_WRONLY|_O_CREAT|_O_EXCL|_O_BINARY on Windows). If the file already
     exists, fd < 0 and PairedArtifact::write records "cannot create paired artifact
     (exists or exclusive creation unsupported); nothing overwritten" and returns
     WITHOUT writing. So a name collision preserves the existing file and does not
     overwrite it.
  4. Validity gate: the artifact is written only when every replicate in BOTH conditions
     is valid (same pre-condition calibrate() requires). If any replicate is invalid,
     PairedArtifact::write records "refused to write paired artifact: a/an ...
     replicate is invalid" and returns WITHOUT writing.
  5. Timing: the write happens AFTER all pairing data exists (post-schedule loop) and
     BEFORE cleanup.perform() and BEFORE main() renders stdout. So the run-owned blob
     and run dir still exist when the artifact is written; the artifact itself is
     NOT removed by BlobCleanup (cleanup.remove only the blob and run dir, never the
     CSV). Therefore the artifact survives the run.
  6. Failure mode: every write failure path sets PairedArtifact::note and returns
     WITHOUT overwriting (fdopen failure, fflush failure, fsync/commit failure, or
     pre-existing file). No retry-overwrite fallback exists.
