ARCHITECTURE (v5; measurement-only change in tests/diag_highres_frequency.cpp)
  1. Query the machine/system logical-CPU mask FIRST. Require bits 0 and 1;
     abort with an explicit message otherwise (documented limitation path).
  2. Do NOT narrow the process affinity to a single CPU (that was the v3/v4
     root cause: SetThreadAffinityMask cannot grant a CPU outside the
     process mask, so the collector stayed on CPU0). The process mask is
     widened to at least {CPU0, CPU1} ONLY so that per-thread pinning can
     take effect; widening alone is explicitly NOT treated as separation.
  3. Benchmark worker (main thread): SetThreadAffinityMask -> CPU0.
  4. Collector thread: SetThreadAffinityMask -> CPU1 (the bit after CPU0
     in the verified system mask; falls back only if CPU1 absent, which is
     recorded as a limitation).
  5. ACTUAL effective affinity of BOTH threads is verified AFTER setting:
     - per-thread readback where the OS provides it, AND
     - runtime evidence: every collector sample and every benchmark
       iteration records GetCurrentProcessorNumber(); the observed CPU set
       is written to the JSON per exec. The run is judged on observed
       placement, not on the set call's return value alone.
  6. Affinity evidence recorded per exec:
     effective_worker_cpus[], effective_collector_cpus[] (observed),
     worker_set_api_return/last_error, collector_set_api_return/last_error,
     process_mask_raw, system_mask_raw.

PERTURBATION CHECK (A/B), predeclared
  A. Benchmark exec with NO collector active (collector thread stopped).
  B. Identical benchmark exec with the collector active (tight loop on CPU1).
  Same op, same warmup=10/measurement=50, same config, same power scheme.
  Order alternates across pairs (A,B then B,A ...) to avoid order bias.
  Material perturbation threshold (fixed before the run):
     |median(B) - median(A)| / median(A) * 100 > 2.0%  => MATERIAL
     <= 2.0% => not material (timing noise band).
  Reported per bench (B6, B9, B7) and pooled.

COVERAGE RULE (unchanged floor, applied honestly)
  Usable coverage floor: >=10 usable in-window samples per
  COLLECTOR-ACTIVE exec. Executions below the floor are reported as
  "not measurable" and are NEVER treated as evidence of stability.
  Zero-coverage B execs are listed explicitly in the analysis.

CLASSIFICATION FRAMEWORK (unchanged: highres_predeclaration.txt + R1-R4)
  A = genuine within-execution frequency variation:
      exec-only spread >5.0% OR >=2 in-exec transitions in compute benches
      (B6/B9), corroborated by iteration timing drift >5.0%.
  B = sampling/measurement artifact: exec-only spread <=2.0% AND <=1
      transition while exec-window spread stays >5.0%.
  C = mixed/indeterminate, or coverage <10 samples/exec, or PDH inadequate.
  PDH adequacy: P1 distinct-change interval <100 ms AND P2 latency <100 ms.
  (No new classification is invented; no threshold is relaxed.)
